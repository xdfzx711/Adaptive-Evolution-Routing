# GEPA 接入代码 Review

范围：`gepa_prompt_evolver`、隔离试跑服务、反思 Provider 装配、可选运行时工作区/超时参数和现有日志的扩展。没有修改主控制器的执行逻辑、接受公式、评分公式或现有实验默认 Operator。

## 检查与修正

1. **公开 Snapshot 不能直接重建 Agent。** ContextBuilder 会过滤配置字段。试跑服务改为按精确 version_id 只读加载完整冻结版本，核对请求视图，再构建内部实例。真实 GEPA + SingleCallAgent、Codex 协议 fixture 两条端到端测试均通过。
2. **GEPA 会捕获反思异常并尝试 fallback。** 适配层记录首个失败，阻止重复远端调用，并将失败传播为标准 EvolutionResponse。测试确认只产生一次真实调用且成本保留。
3. **ModelResponse.usage 是 UsageReport。** 转为 ResourceUsage 后再汇总；错误类型、截断响应和未知 usage 均有记录。内部任务执行、评分和反思成本不重复累计。
4. **预算不足不能导出未完成内部选择评测的子候选。** 检查了 1–7 次评测边界；只从完成内部选择评测的候选中导出结果，否则返回带原因的空候选。
5. **收据落盘失败不能丢掉已发生的消耗。** 错误保留完整 usage，并阻止返回无法追踪的候选。
6. **内部和外部运行状态分离。** 每次试跑创建新依赖图、临时 Store 和工作区；内部缓存独立，外部已有仓库只作为只读来源。测试比较试跑前后外层文件和仓库缓存，未发生变化。
7. **隐藏评分信息不进入反思材料。** 复用公开反馈过滤器，针对 Evaluator 私有 prose/metrics 使用 canary 测试；外层 validation/test 和独立任务模式下的其他开发任务被阻止。
8. **日志格式和关系可追踪。** 内部记录使用时间、C1/C2 和试跑序号，完整内容展开在当轮 record.json；evolution.txt 区分内部接受与外层接受/提交。删除临时测试报告后，可以仅凭已保存工件离线重建。

## 初版接入验证结果

- 全量测试：`python -m unittest discover -s tests`，457 项，456 通过、1 跳过。
- Review 后定向回归：GEPA 单元/集成与隔离仓库缓存测试，17 项全部通过。
- 现有 Codex 默认工作区行为、旧插件注册、旧环境变量、配对验证、接受、存储和日志测试通过。
- GEPA 使用官方 0.1.4 引擎，任务模型和反思 Provider 使用离线替身；没有调用真实 Qwen、JEV 或 Codex 模型服务。

检查后未发现阻断接入的问题。实例和文件状态隔离不提供操作系统沙箱保证；真实服务的可用性与模型输出效果仍需在用户配置反思模型后实跑确认。

## 2026-10-27 运行后插件修复复查

- Windows MXC 的 TEMP 整体 deny 和内部试跑父目录 deny 会遮蔽任务目录授权。Codex 插件改用 read-only 父方案、默认 deny、精确工作区 write 授权；其他任务目录和 AER 项目仍不可读。原生测试覆盖外层与 GEPA 内部目录布局。
- Git 通过每次任务的 shell 环境信任精确工作区，跳过宿主全局 Git 配置，处理 MXC 用户与仓库所有者不同的问题。未使用 safe.directory=*。
- GEPA 插件按 episode、任务和执行配置保存已生成提示词。重复生成时不执行任务，默认再反思一次；仍重复时正常结束搜索，保留原因与已发生的费用。模型或工具变化后允许重新尝试相同提示词。
- 当前实验内部评测额度改为 8。连续两个改善候选的测试实际执行 7 次任务评测，并完成第二个候选的选择集评分。
- 全量测试 467 项，465 通过、2 跳过；两项原生 MXC/CLI 检查另行启用并通过。最终父目录授权修正后，36 项针对性回归通过。
- 本轮仅调整插件、实验配置、测试与文档，主控制器、评估、接受和提交逻辑保持原样。原生 CLI 集成检查使用本地模拟 Responses 服务；修改后的完整五轮远端实验尚未重跑。

## 2026-10-28 三次采样与内部结果复用复查

- **采样与比较口径一致。** 每个 Prompt/任务默认三次独立执行，使用算术平均分初筛和排名；反思保留三次公开反馈和轨迹。测试验证候选即使单次达到 1.0，三次均值低于原版时仍被拒绝。
- **复用不重复执行、计费或丢失轨迹。** 缓存限定于一次 GEPA 搜索，键包含 Prompt、任务、Snapshot、请求执行配置及采样配置。初始选择集评测后可以直接提供反思轨迹；子候选排名复用试跑组。不同任务、版本、执行配置和搜索调用不混用。返回的公开数据采用防御性复制。
- **额度按实际采样计数。** GEPA 引擎按任务示例计数，不能准确反映三次采样及插件缓存命中，故使用插件原有 SearchRecord 按真实试跑记录强制限制。保留上限 8 时最多完成两组三次采样，剩余两次不开始新组；上限 9 的测试确认两个连续改善候选均完成排名。
- **不使用不完整组。** 开始批量评测前检查所需完整组额度；组内异常或超时保留逐次执行和成本，不缓存、排名或导出不完整组。中途异常不会伪装成零分。
- **沿用现有日志。** 在 evolution.txt、当轮 record.json 和优化收据中记录三次分数、平均分、总体标准差、请求种子与结果复用，不增加日志文件；离线重建测试通过。
- **兼容范围。** 本轮仅修改 GEPA 插件、其配置、报告展示、测试和文档。任务执行模型、Qwen/JEV 依赖、外层评分与接受提交流程保持原有行为。
- **验证结果。** GEPA 定向测试 29 项全部通过；完整测试 476 项，474 通过、2 项原生 MXC/CLI 可选测试跳过。真实 GEPA 引擎、SingleCallAgent 和 Codex 协议 fixture 集成通过；本轮未调用真实远端模型重跑 Benchmark。
