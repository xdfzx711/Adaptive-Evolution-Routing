# HotpotQA 插件与 Fixed-GEPA baseline review

日期：2026-11-03。范围：HotpotQA 数据/评分插件、通用任务清单、原生评分一致性约束、批量运行入口、实验配置及测试。

## 代码检查结果

检查后未发现阻断本期使用的问题。现有实验配置、GEPA 搜索算法、Router 实现、配对验证、接受公式及版本提交逻辑均未改动。

1. **原生评分对齐。** 官方源码固定在 `3635853403a8735609ee997664e1528f4480762a`；只替换 JSON 库导入。测试恢复导入行后比对上游文件哈希，并将包装器输出的全部十二项指标与官方脚本比较。覆盖答案规范化、yes/no/noanswer、部分正确、重复证据、缺失字段、错误标题/句子编号。缺失答案不抹掉合法证据字段的原生成绩。
2. **内外评分一致性。** 新增可选 `NativeEvaluationProvider` 协议。HotpotQA 声明原生 evaluator，装配时检查内外 evaluator ID 与默认值规范化后的配置一致；内部试跑再次检查。没有声明该协议的旧 benchmark 保持原行为，已有 SWE-bench 混合评分配置未被改写。
3. **逐任务留出任务。** 通用清单要求每个开发任务恰有一份映射；similar/regression 非空、无重复、来自各自角色池。角色池与当前任务及最终测试任务隔离。源文件中重复 ID、缺失 ID、错误校验和被拒绝。生成规则只依赖类型、ID 和固定种子，不使用答案或执行成绩。
4. **数据与状态隔离。** 标准答案及标准证据只存在于私有评分规格；公开任务只含问题、上下文和输出契约。GEPA 内部仍限于当前 independent 任务，不能获取留出任务。解析缓存保存选中行的序列化文本，各插件实例反序列化为独立对象；内部运行工作区、版本和执行状态沿用既有隔离机制。
5. **缓存与可复现性。** 数据文件哈希及任务清单内容决定数据版本；清单变化会使验证条件变化。修正了生成文件的换行及相对路径，保证 Windows/Linux 数据校验和与路径表示一致。固定上游脚本的 LF 换行，防止 Git 自动换行破坏哈希验证。
6. **报告正确性。** Review 修正了批量摘要读取初始评分的字段：已有 round 报告在生成候选后使用 `evaluation_before_evolution`。摘要分别保存初始/最终分数、内部候选、接受分解及版本；错误与未评估任务单列，均值明确使用的分母；无法核算的错误不伪造零消耗。官方格式预测文件只包含实际输出，不补造缺失答案。
7. **现有功能兼容性。** 旧命令保留原处理分支；新 `run-benchmark` 单独处理。共享接口新增能力均为可选。`pyarrow` 只是数据准备的 optional extra，不进入运行和评分依赖。既有 toy benchmark 通过新批量入口的测试，证明该入口没有硬编码 HotpotQA。
8. **输出保护。** 批量导出在执行前检查目标路径，不覆盖配置、数据、dotenv、已有文件或托管运行目录。新批次要求新的 run ID，避免隐式重复或混入旧实验。原有单任务入口行为不变。

## 仍需按实验口径解释的限制

- 小批 independent baseline 观察的是逐任务适应和对应留出任务上的效果，不代表一个通用 Prompt 在完整 HotpotQA 上的成绩。
- 已完成任务的 Prompt 对比显示，改善主要来自答案简洁化与 yes/no 输出约束。第一个候选包含当前任务的地点示例，该信息已经出现在公开执行结果中；这不是读取私有标签的证据，但具有任务特化性质，不能据此宣称通用推理能力提升。
- 任务模型存在随机性；三次内部均值与单次外层配对评测不能解释为统计显著性验证。
- 当前控制器尚未强制执行全局累计 Token/时间预算；已有 GEPA 内部次数和时间限制仍生效。实际消耗已如实记录，未以配置值充当费用上限。
- 本期实现 distractor；fullwiki 检索环境不在本次范围内。
- 官方 dev 的预留子集没有参与本轮优化；它不是隐藏官方 test。
