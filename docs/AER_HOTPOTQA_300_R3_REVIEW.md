日期：2026-11-04。范围：新 HotpotQA baseline 配置、通用批运行器、任务级进程隔离、接受策略记录。

## 复核结果

本轮自查与回归测试后，未发现阻塞本次功能的遗留问题。原一轮配置、数据清单和运行记录保留。
控制器与加权接受插件已有所需算法，复用其实现，通过新配置启用三轮、成功提前停止、0.04 收益阈值、
0.10 逐轮回归容忍度。没有修改其他实验的策略默认值。

检查并验证了以下路径：

- 初始成功不进化；接受且成功提前结束；拒绝后继续使用稳定版本；接受但未成功继续进化；
  三轮结束保留最后提交版本；复用候选当前题执行结果，提交后不重复执行/评分。
- 收益恰好 0.04、回归恰好下降 0.10 可接受；收益不足及回归超限分别拒绝。
- Windows spawn 三进程同时运行，使用文件屏障验证重叠；完成任务后补入第四个任务。
  串行与并行的确定性指标、模型调用数一致，Token 汇总等于各任务实际用量之和。
- 每个子运行独立持有版本、日志和缓存；父汇总按原任务顺序落盘，工件可按任务 `run_root` 定位。
- 三个进程实际运行 GEPA、HotpotQA 官方评分器、接受与提交、初始/最终留出报告和预测导出。
  测试使用本地固定模型响应，不调用付费模型。
- 普通子任务异常不阻塞其他任务；进程异常退出导致池失效时，为其余请求保留明确错误记录。
  失败任务的留出题计入缺失分母，未知用量不写作零。
- 连续模式拒绝多进程；无 `--workers` 时维持串行行为；旧 CLI、控制器、评分和验证测试通过。

实现复核中补齐了“worker 初始化失败时留出题从分母消失”的边界问题，并加入回归测试。

## 首次真实批运行失败后的补充复核

用户的 `hotpotqa-fixed-gepa-300-r3p3-v1` 在 14.32 秒内把 300 个任务标记为
`BrokenProcessPool`，没有创建子任务运行目录。旧日志只保存这一层错误，未保存 cause，
因此无法从该记录恢复最先触发的底层异常；这些记录不能当作 300 道题的实际作答失败。

进一步确认了旧实现的异常跨进程缺陷：`ConfigError` 和 `AERError` 的构造函数要求额外参数，
直接通过进程池传递异常会在父进程反序列化时触发 TypeError，继而使进程池失效。
此前测试覆盖了普通 RuntimeError 与进程退出，但未覆盖这些框架启动异常。

修复：子进程边界捕获并返回结构化数据，保留可用的用量与错误类型；父进程保存
`worker_error.json` 并输出具体原因。进程池错误还保留可用的 cause。
spawn 子进程补齐 CLI 的 UTF-8 输出初始化。

新增真实 spawn 回归用例：前两题分别触发 ConfigError、PluginConfigurationError，
后两题仍正常完成；错误详情可读、已知零用量保留。相关批处理、GEPA 和接受策略共 29 项测试通过，
包括 CLI `python -m experiments run-benchmark --workers 3` 入口及 stdout/stderr UTF-8 输出测试。
真实三任务零轮启动检查也已完成，三个任务均正常执行并返回官方评分。

完整真实模型检查：`runs/hotpotqa-r3p3-real-smoke-fix2/baseline_summary.json`。
使用原三轮配置、`--workers 3 --limit 3 --report-holdouts`，最终 status=completed，error_tasks=0，
三题留出报告均为 complete，墙钟时间 682.28 秒，总计 1,329,464 Token。
第一题执行三轮后保留初始版本（Joint F1=0.6）；第二题初次成功、零轮进化；
第三题第三轮候选通过外层验收并提交，Joint F1 从 0.8 升到 1.0，随后成功停止。
该检查验证真实三路运行及完整闭环，不代表完整 300 题已重新运行，也不能恢复旧运行遗漏的首个异常。
